# Extraction yt-dlp d'une vidéo connue — où partent les millisecondes (lot « Sillon vitesse », S3, 24/10)

L'ouvrier yt-dlp PRÊTÉ par l'hôte (`apps/backend/src/plugins/runtime/tools/workerScript.ts`,
protocole fermé) fait, pour une extension, l'extraction « vidéo connue → URL audio directe ».
yt-dlp 2026.10.21 (zipapp en service), Python 3.14, Mac du banc.

## Banc

`apps/backend/test/octave-runtime/extractBench/` : le VRAI programme de l'ouvrier sous son
amorçage, avec une couche réseau de banc entre les deux (`netShim.py`) qui trace chaque requête
HTTP et le solveur JS, enregistre les réponses (`record`) et les REJOUE sans réseau (`replay`,
`--net` pour rejouer les latences mesurées). Une réponse se dépense une fois, toutes les variantes
se mesurent ensuite hors réseau. Les enregistrements portent l'adresse IP publique dans les URL :
jamais dans le dépôt.

Chaque requête rouvre sa connexion (le gestionnaire urllib de yt-dlp, sans `requests` dans
l'image) : DNS 5 + TCP 10 + TLS 31 ≈ 46 ms par requête, mesurés.

## À savoir

- Sans page watch ni `initial_data`, yt-dlp perd `channel` et `uploader` (l'ouvrier les reprend de
  `videoDetails.author`) ; `track`, `artists`, `album` d'une piste « Auto-generated by YouTube »
  viennent de la description et restent (métadonnées identiques sur 8 titres réels ; jugement de Sillon identique sur les 3 jugés). Le
  Song / Artist / Album d'un CLIP non auto-généré se lit, d'après le code de yt-dlp
  (`metadataRowRenderer`), dans `initial_data` : non mesuré.
- Ouvrier et version : au démarrage, la copie à jour de yt-dlp prend le relais ~1 s APRÈS le
  lancement des ouvriers ; ils restaient sur l'épinglé tant que l'extension gardait sa connexion
  (banc : trois ouvriers en 2026.08.19, copie en 2026.10.21). Un ouvrier au repos suit désormais
  le zipapp en service (contrôle toutes les 30 s), connexion intacte.
- Un flux audio lu SANS Range est bridé par googlevideo (~32 Ko/s), quel que soit le client ;
  en Range, 4 Mo en 0,13 s (visionos) ou 0,67 s (défaut).
- Les bandes-annonces n'utilisent pas cet ouvrier (`services/trailers/ytExtract.ts`, la CLI) :
  rien ne change pour elles.
